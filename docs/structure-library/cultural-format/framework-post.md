# Framework Post

**Entry id**: `framework_post`

**Scope**: A compact professional post teaches a named or memorable framework for understanding or doing something.

**Structure grounding**: Platform-era educational post and professional writing pattern.

**Grounding status**: `provisional`

**Grounding tier**: `platform_pattern_evidence`

**Use when**: The reader should leave with a portable mental model, steps, lenses, or decision tool.

**Audience promise**: The reader will get a clear framework they can remember and apply.

**Audience Hook logic**: Begin with a common problem, confusing choice, costly mistake, or compressed claim that creates need for the framework.

**Expected parts**:

| Part | Function | Default policy |
| --- | --- | --- |
| Problem frame | Names the confusion or decision the framework solves. | Required |
| Framework reveal | Introduces the named model, steps, lenses, or parts. | Required |
| Parts breakdown | Explains each part in usable terms. | Required |
| Example | Shows the framework in action. | Required |
| Application guidance | Tells the reader when and how to use it. | Required |
| Limitation or caveat | Prevents overuse or false precision. | Mergeable |

**Turn or payoff behavior**: The payoff is usability: the reader can now sort a messy situation with the framework.

**Pacing norms**:

- Get to the framework quickly.
- Keep each part parallel and scannable.
- Use one strong example rather than many shallow examples.
- Place caveats near application guidance.

**Required decisions**:

- Is the framework a sequence, checklist, matrix, set of lenses, or diagnostic?
- What problem does it actually solve?
- What example proves it works?
- Where should the framework not be used?

**Common failure modes**:

- The framework is just renamed common sense.
- The parts overlap or are not parallel.
- The post explains the topic but never becomes a tool.
- The caveat is missing, making the model feel brittle.

**Adaptation questions**:

- What should the reader be able to classify, decide, or do?
- What is the smallest memorable version?
- Which part is most likely to be misunderstood?
- What real example can carry the explanation?

**Recommended Stewardship Views**:

- `step_checklist`
- `decision_tree`
- `risk_caveat_map`
